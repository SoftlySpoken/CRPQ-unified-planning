# Testing Custom Planner Integration

This document outlines the steps to test the custom planner integration within MillenniumDB, including comparison with the original planner and metric collection.

## Prerequisites

1.  **MillenniumDB Build**: Ensure you have successfully built MillenniumDB in Release mode.
    ```bash
    cmake -B build/Release -D CMAKE_BUILD_TYPE=Release && cmake --build build/Release/
    ```
2.  **Python Dependencies**: Install `sparqlwrapper` for running SPARQL queries.
    ```bash
    pip3 install sparqlwrapper
    ```
3.  **Test Data**: The `example.ttl` data file will be used for testing.

## Setup

1.  **Import Test Data**: Import the `example.ttl` data into the `temp_db` directory.
    ```bash
    build/Release/bin/mdb-import tests/sparql/test_suites/internal/example/example.ttl temp_db
    ```
2.  **Create a Sample Query File**: For demonstration, we'll use a simple query that hits `OpBasicGraphPattern`. Create a file named `simple_query.rq` with the following content:
    ```sparql
    PREFIX : <http://www.firstPrefix.com/>

    SELECT *
    WHERE {
        :subjectFirstPrefix :predicateFirstPrefix ?x .
    }
    ```

## Running the Server and Queries

1.  **Start `mdb-server` with Planner Comparison**:
    This command starts the MillenniumDB server, enabling the custom planner, running both planners for comparison, showing verbose output, and saving the metrics to a CSV file.

    ```bash
    build/Release/bin/mdb-server temp_db --port 8080 --custom-planner --custom-planner-compare --custom-planner-verbose --custom-planner-output planner_metrics.csv
    ```
    *Keep this terminal open as the server needs to be running.*
    [TODO: When only run custom planner, remove the --custom-planner-compare parameter; when only run original planner, remove all parameters after the port.]

2.  **Execute the Query**:
    In a *new terminal*, execute the sample SPARQL query using the Python script.

    ```bash
    python3 scripts/sparql_query.py simple_query.rq
    ```
    You should see the query results in this terminal.

## Analyzing the Output

1.  **Server Console Output**:
    In the terminal where `mdb-server` is running (Step 1 of "Running the Server and Queries"), you will observe verbose output detailing the planning process for both the original and custom planners. This includes:
    *   `Original planner:` and `Custom planner:` logs.
    *   Estimated costs for plans.
    *   Error messages if a planner fails.
    *   A comparison summary generated by `PlannerMetricsReporter::print_comparison`.

2.  **`planner_metrics.csv` File**:
    After executing the query, a file named `planner_metrics.csv` will be generated in the directory from which you started the `mdb-server`. This file will contain structured data for each planner's execution, including:
    *   `planner_type`: "original" or "custom"
    *   `num_triple_patterns`, `num_path_patterns`
    *   `planning_time_ms`, `execution_time_ms`
    *   `estimated_cost`
    *   `plan_description`
    *   Possible `error` messages.

    You can open this CSV file with any spreadsheet software to analyze the metrics.

## Clean Up (Optional)

1.  **Stop `mdb-server`**: Stop the server by pressing `Ctrl+C` in the terminal where it's running.
2.  **Remove Temporary Database and Query Files**:
    ```bash
    rm -rf temp_db
    rm simple_query.rq
    rm planner_metrics.csv
    ```

This detailed guide should help you verify the custom planner's behavior and performance.
